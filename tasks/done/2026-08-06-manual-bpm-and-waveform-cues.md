# BPM・開始位置の手動指定と、波形の再生位置表現

## 要件

### AnalysisStatus

- [x] BPM の次に開始位置を ms 単位で表示
- [x] BPM と開始位置を調整・リセットできるようにする

### 波形プレビュー

- [x] 開始位置よりマイナスの拍・小節調整が入ったときの補正表示（見た目だけ）
- [x] 拡大側で、再生中の小節以外に薄いグレーを重ねて再生位置を表す

## 設計

### BPM / 開始位置を触ると等間隔グリッドへ切り替わる

BPM を変えることには「検出した拍位置を捨てて、BPM と開始位置から等間隔のグリッドを
作り直す」以外の解釈がない。開始位置だけを動かす方式も考えたが、それでは `拍の調節`
と機能が重複し、同じ操作が状況によって別の意味になってしまう。

- どちらかを触ると手動グリッドへ。もう一方は現在値のまま引き継ぐ
- 「検出値に戻す」で解析結果へ復帰する
- 手動グリッドでは特徴量と拍が対応しないので、位相の自動推定は使わず開始位置が
  そのまま 1 拍目になる（`estimatedPhase = 0`）
- どちらの編集も「表示している開始位置を保つ」ように原点を逆算する。BPM を変えても
  曲の頭の位置がずれない

### 音源より手前の区間

`開始する小節` をマイナスにすると 1 拍目が t < 0 を指す。波形は t >= 0 しか無いので
何も見えず、再生されているのか分からなかった。

- 全体表示の時間範囲を `-leadIn` から始めて、その区間を斜線で塗る
- 鳴っている範囲に薄いアクセントの帯を敷く（波形が無くても位置が分かる）

### 拡大側の小節ハイライト

再生中の小節の外側に背景色を 62% で重ねる。明るいテーマでは白く、暗いテーマでは
黒く沈むので、どちらでも「引っ込んで見える」側へ寄る。

あわせて全体波形のクリックを「拡大表示を動かす」から「その位置から再生する」へ変えた。
拡大表示は常に再生中の小節を追うようになったので、表示位置だけを動かす操作は不要。

### 検証結果

テストトーン（120BPM）での数値確認:

| 操作 | manual | BPM | 開始位置 | 拍 | 小節 | ticks |
| --- | --- | --- | --- | --- | --- | --- |
| 初期（検出） | false | 119.984 | 488 ms | 499 ms | 15 | 64 |
| BPM を 130 に | true | 130 | **488 ms（維持）** | 462 ms | 17 | 69 |
| 開始位置を 500ms に | true | **130（維持）** | 500 ms | 462 ms | 17 | 69 |
| BPM を 65 に | true | 65 | **500 ms（維持）** | 923 ms | 8 | 35 |
| 検出値に戻す | false | 119.984 | 488 ms | 499 ms | 15 | 64 |
| 開始する小節 -1 | false | 119.984 | **-1509 ms** | 499 ms | 16 | 64 |

拡大側のハイライトは、キャンバスの画素で範囲を実測して確認した。

- 小節幅 1.997 秒 / 表示幅 4.001 秒（2 小節）
- 小節は x 220〜660（キャンバス幅 880）＝ちょうど中央 50%
- 小節の外側だけ α=158（0.62 × 255）のオーバーレイが乗っている

コンソールにエラー・警告なし。アプリ本体は gzip 21.0KB → **22.1KB**。

### 残課題・申し送り

- 手動グリッドは等間隔なので、テンポが揺れる曲では後半でずれる。テンポ一定の曲を
  直すための機能で、揺れる曲には検出モードのほうが向く
- 全体波形のクリックがシークになったので、拡大表示だけを動かす操作は無くなった
